# Архитектура AnimeSoul

## Поток данных

```text
Браузер → /api/yummy → YummyAnime API
                       ├─ каталог и метаданные
                       └─ iframe-ссылки видеопровайдеров

Браузер → localStorage
          ├─ профили конфигурации
          ├─ избранное и папки
          ├─ прогресс серий
          ├─ отслеживание озвучек
          └─ тема и настройки плеера
```

Публичный API-токен читается только на сервере. Клиент обращается к локальному маршруту `/api/yummy`, поэтому секреты не включаются в клиентскую сборку.

## Серверный адаптер

`app/api/yummy/route.ts` изолирует внешний API от интерфейса. Поддерживаемые режимы:

- `catalog` — выдача, поиск и пагинация;
- `details` — восстановление сохранённых тайтлов по ID;
- `videos` — детальная карточка и список видео.

Если появится новый поставщик, добавьте отдельный адаптер с едиными внутренними типами, а выбор поставщика оставьте на сервере.

## Клиентское состояние

Сейчас прототип намеренно использует `localStorage`. Ключи сгруппированы в объекте `K` в `app/page.tsx`. Экспортируемый `ConfigSnapshot` является переносимым контрактом пользовательских данных.

При развитии рекомендуется вынести:

```text
app/
  components/
    catalog/
    library/
    player/
    settings/
  lib/
    api/
    storage/
    progress/
  types/
```

Существующий одностраничный файл можно разделять постепенно: сначала вынести чистые типы и функции хранилища, затем крупные визуальные блоки.

## Прогресс

Прогресс хранится по ключу `сезон:серия`. Папка вычисляет:

```text
полностью просмотренные серии всех тайтлов
──────────────────────────────────────────
общее количество серий всех тайтлов
```

Серия считается просмотренной при достижении 90%. Порог следует вынести в настройку, если появятся разные режимы учёта.

## Плееры

Одна озвучка и серия могут иметь несколько источников. Интерфейс предпочитает Kodik, поскольку он поддерживает команды и события через `postMessage`. Для других iframe-плееров гарантируется только встраивание; доступность управления зависит от поставщика.

## Направления расширения

- заменить `localStorage` на SQLite/D1/PostgreSQL через интерфейс репозитория;
- добавить обычную локальную или серверную авторизацию;
- вынести фоновые проверки новых серий в cron-задачу;
- добавить тесты адаптера API и миграций конфигурации;
- версионировать `ConfigSnapshot` и писать миграции для старых экспортов;
- добавить кэширование каталога и ограничение частоты внешних запросов;
- подключить альтернативные легальные каталоги и видеопровайдеры.

## Безопасность

- Никогда не коммитьте `.env.local`.
- Для приложения нужен только публичный application token.
- Не сохраняйте приватные API-токены в браузере или экспортируемом конфиге.
- Проверяйте происхождение iframe URL и условия поставщика перед публичным релизом.
