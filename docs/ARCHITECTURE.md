# Архитектура AnimeSoul

## Поток данных

```text
Браузер → /api/yummy → YummyAnime API
                       ├─ каталог и метаданные
                       └─ iframe-ссылки видеопровайдеров

Браузер → http://127.0.0.1:3002/storage → data/animesoul-storage.json
          ├─ профили конфигурации
          ├─ избранное и папки
          ├─ прогресс серий
          ├─ отслеживание озвучек
          ├─ история и скрытые элементы «Смотрю сейчас»
          └─ тема, профили и настройки плеера

Браузер → localStorage (резервное зеркало и первичный перенос старых данных)
```

Публичный API-токен читается только на сервере. Клиент обращается к локальному маршруту `/api/yummy`, поэтому секреты не включаются в клиентскую сборку.

## Серверный адаптер

`app/api/yummy/route.ts` изолирует внешний API от интерфейса. Поддерживаемые режимы:

- `catalog` — выдача, поиск и пагинация;
- `details` — восстановление сохранённых тайтлов по ID;
- `videos` — детальная карточка и список видео.
- `schedule` — доступный график следующего выхода.

Если появится новый поставщик, добавьте отдельный адаптер с едиными внутренними типами, а выбор поставщика оставьте на сервере.

## Локальное хранилище

`local-storage-server.mjs` запускается батником вместе с сайтом и атомарно записывает документ в `data/animesoul-storage.json`. `localStorage` остаётся резервным зеркалом: при первом обновлении существующие браузерные данные автоматически переносятся в файл.

`StorageDocument.schemaVersion` задаёт версию всего хранилища, а `ConfigSnapshot.version` — версию переносимого профиля. `migrateDocument` и `migrateSnapshot` дополняют старые документы новыми полями со значениями по умолчанию. Поэтому экспорт из старой версии можно импортировать после обновления приложения.

Перенос выполняется экспортом/импортом профиля через интерфейс либо копированием `data/animesoul-storage.json` при остановленном приложении. Файловый способ переносит весь документ со всеми профилями, а экспорт — один выбранный снимок конфигурации.

При развитии рекомендуется вынести:

```text
app/
  components/
    catalog/
    library/
    player/
    settings/
  lib/
    api/
    storage/
    progress/
  types/
```

Существующий одностраничный файл можно разделять постепенно: сначала вынести чистые типы и функции хранилища, затем крупные визуальные блоки.

## Прогресс

Прогресс хранится по ключу `сезон:серия`. Папка вычисляет:

```text
полностью просмотренные серии всех тайтлов
──────────────────────────────────────────
общее количество серий всех тайтлов
```

Серия считается просмотренной после полного воспроизведения либо достижения начала эндинга, если API передал его таймкод. Прогресс карточки рассчитывается по просмотренному времени.

`EpisodeState` также накапливает фактически проигранные секунды и количество завершений. Повторное прохождение серии определяется после возврата к её началу и следующего достижения конца. Эти поля используются страницей статистики; старые сохранения получают базовое первое завершение автоматически, а точные пересмотры начинают накапливаться после обновления.

## Отслеживание релизов

Подписка хранит ID всех элементов франшизы, выбранные озвучки, последнее подтверждённое количество серий и число непросмотренных новинок. На главной странице проверка запускается сразу и затем каждые пять минут.

Количество обновляется только после успешного ответа по всем элементам франшизы. Это защищает от ложных уведомлений и сброса базы при частичном отказе API. Уже учтённая серия повторно новой не становится; после её просмотра счётчик новинок уменьшается.

## Плееры

Одна озвучка и серия могут иметь несколько источников. Интерфейс предпочитает Kodik, поскольку он поддерживает команды и события через `postMessage`. Для других iframe-плееров гарантируется только встраивание; доступность управления зависит от поставщика.

## Направления расширения

- при необходимости заменить JSON-файл на SQLite/D1/PostgreSQL через интерфейс репозитория;
- добавить обычную локальную или серверную авторизацию;
- вынести фоновые проверки новых серий в cron-задачу;
- расширить тесты адаптера API и миграций конфигурации;
- добавить кэширование каталога и ограничение частоты внешних запросов;
- подключить альтернативные легальные каталоги и видеопровайдеры.

## Безопасность

- Никогда не коммитьте `.env.local`.
- Для приложения нужен только публичный application token.
- Не сохраняйте приватные API-токены в браузере или экспортируемом конфиге.
- Проверяйте происхождение iframe URL и условия поставщика перед публичным релизом.
