# Общий поиск

Кнопка поиска находится в общей шапке сайта: в каталоге, на страницах аниме, серий,
профилей и аккаунта. Нажмите её, **Ctrl+K** (**Cmd+K** на macOS) или **/**,
когда курсор находится вне текстового поля. Поиск плавно разворачивается, подсвечивается,
а фон затемняется. При включённом уменьшении движения анимация отключается.

Окно поиска занимает до 1180 пикселей по ширине и адаптируется к высоте экрана.
На широком экране аниме и остальные категории показаны рядом; на узком — одной колонкой.
У результатов общая вертикальная прокрутка без ограничений высоты отдельных разделов.
Пустой поиск содержит только три популярных сейчас
аниме и быстрые настройки: тема, профиль, приватность, безопасность, почта/Google.
При вводе запроса остаются только категории с совпадениями. Если подходит одна
категория, результаты показаны без заголовка и разделителей; если несколько —
у каждой есть заголовок. Настройки подобраны как быстрые ссылки,
а не по измеренному рейтингу использования. Для аниме сначала учитывается число разных
аккаунтов с записанным прогрессом просмотра за последние семь дней. При равенстве или
отсутствии свежих просмотров используются популярность из каталога, оценка Shikimori
и название. Это статистика просмотров AnimeSoul, а не мировой рейтинг популярности.

У аниме также показано количество серий: известное общее число и, для онгоингов,
сколько серий уже вышло. Числа берутся из метаданных каталога и зарегистрированных
серий; неизвестное общее число не угадывается.
После входа шкала и статус просмотра используют сохранённый прогресс этого аккаунта
и отметки о завершении просмотра.
Недосмотренная серия учитывается по сохранённой позиции, если известна её длительность.
Если у онгоинга просмотрены все вышедшие серии, он отмечается как просмотренный
до текущей серии, а не как завершённый тайтл. Отсутствие прогресса означает отсутствие
записанного просмотра в AnimeSoul; это не доказывает, что человек никогда не видел
аниме на другом сайте. Гостям личный статус и шкала просмотра не показываются.

После 900 мс неподвижного наведения появляется увеличенный предпросмотр выбранной
карточки. Аниме показывает постер, название, оценки, серии, личный прогресс и описание;
персонаж — описание, сэйю и связанные аниме с ролями; человек — доступные зрителю
разделы профиля и статистику. Настройки и фильтры показывают назначение и действие.
Мелкое дрожание курсора в пределах 6 пикселей допускается; заметное движение,
прокрутка, ввод или закрытие поиска убирают виджет. Клик по карточке открывает сущность
или применяет фильтр. Выбор стрелками также показывает предпросмотр после паузы;
сенсорное нажатие сразу открывает результат. Подробности персонажей и профилей
загружаются только при открытии виджета; запрос отменяется при его закрытии.
Профиль возвращается без кеширования с теми же ограничениями видимости, что и его страница.

## Названия, люди и настройки

Аниме находится по русскому/оригинальному названию и импортированным альтернативным
названиям. Поддерживаются распространённые сокращения `АОТ`/`AOT`/`SNK`, `КРД`/`KNY`,
`JJK`, `МГА`/`MHA`/`BNHA`, `SAO` и `DN`. Поиск учитывает небольшие опечатки и случайную
смену русской/английской раскладки; неизвестные сокращения автоматически не угадываются.

Человека можно найти по нику, в том числе с `@`, или полному UUID аккаунта. Для поиска
по нику нужно не менее двух символов. Гостям доступны публичные активные профили.
После входа также видны собственный профиль и доступные профили для друзей;
блокировка в любом направлении исключает человека из результатов. Ответ содержит
только ник, аватар и публичный идентификатор, без почты и закрытых разделов профиля.

Результаты настроек ведут к существующим полям на `/account`:

| Результат               | Адрес                          | Поля                                                        |
| ----------------------- | ------------------------------ | ----------------------------------------------------------- |
| Тема оформления         | `/account#appearance-settings` | Лиловая или Графит — две тёмные палитры на этом устройстве  |
| Настройки профиля       | `/account#profile-settings`    | Имя, описание, аватар, обложка и статус                     |
| Приватность и видимость | `/account#privacy-settings`    | Доступ к профилю/разделам, заявки в друзья и индексация     |
| Безопасность аккаунта   | `/account#security-settings`   | Пароль и второй фактор для административного доступа        |
| Почта и Google          | `/account#identity-settings`   | Подтверждение/смена почты, привязка Google и восстановление |

Тему можно менять без входа. По умолчанию выбрана «Лиловая», а «Графит» использует
нейтральные серо-синие фоны и акценты. Обе палитры тёмные. Браузер сохраняет выбор
на этом устройстве; через аккаунт он не синхронизируется. Для остальных настроек
сначала нужен вход, затем выбранный раздел прокручивается в поле зрения после загрузки
данных. Для аккаунта без пароля ссылка безопасности ведёт к разделу почты и восстановления. Фильтры уточняют аниме;
люди и настройки ищутся, когда фильтры аниме не заданы.

## Фильтры в строке поиска

Нажмите кнопку фильтра или напишите его ключ с двоеточием. После двоеточия появляются
подсказки. Подсказки жанров берутся из доступного каталога: если значение пустое,
сначала идут популярные. Названия с пробелами заключайте в кавычки.

| Фильтр | Пример                           | Значение                                                  |
| ------ | -------------------------------- | --------------------------------------------------------- |
| Жанр   | `tag:"Психологическое"`          | Аниме этого жанра                                         |
| Статус | `status:онгоинг`                 | `онгоинг`, `вышло` или `анонс`                            |
| Формат | `type:фильм`                     | `сериал`, `фильм`, `ova`, `ona`, `спецвыпуск` или `клип`  |
| Год    | `year:2024` или `year:2020-2026` | Один год или включительный диапазон, в пределах 1900–2200 |
| Оценка | `rating:8+`                      | Минимальная оценка Shikimori от 0 до 10                   |

Фильтры можно объединять и добавлять обычное название, например
`tag:"Психологическое" status:вышло rating:8+ тетрадь`.
Также принимаются `genre:`/`жанр:`, `статус:`, `format:`/`формат:`/`тип:`, `год:`
и `рейтинг:`/`оценка:`. Вместо двоеточия подходит точка с запятой:
`tag;"Психологическое"`. Поддерживается одно значение каждого фильтра;
повторный фильтр заменяет его прежнее значение. Несколько обязательных/исключаемых
жанров в этом синтаксисе пока не поддерживаются.

**↑/↓** выбирают подсказку, **Tab** дополняет её, **Enter** применяет подсказку
фильтра или открывает выбранный результат, **Esc** и клик по фону закрывают поиск.
Если результат не выбран, Enter открывает `/search?q=…`. Длина запроса — до 240
символов. Диалог и страница результатов показывают до восьми аниме и шести людей,
а также подходящие настройки. Для запроса только с фильтрами есть ссылка на весь
каталог с этими фильтрами.

Если подсказка продолжает введённый текст, её остаток показан серым прямо в поле.
Tab дописывает его, сохраняя набранный префикс. При исправлении опечатки, выделении
текста или курсоре в середине строки эта подсказка скрывается. Дополнение фильтра
сохраняет кавычки и следующие фильтры, закрывая незавершённую кавычку. «Очистить»
убирает запрос и оставляет окно открытым; отдельная кнопка закрытия возвращает фокус
в шапку. При новом открытии результаты прокручиваются к началу.

## Реализация и проверки

### Поиск аниме по кадру

Откройте **Поиск по кадру** из поиска в шапке. Страница `/search/frame` доступна из
бургер-меню и карты сайта в футтере. В обычном поиске есть подсказка о вставке и
перетаскивании изображения. Выберите,
перетащите или вставьте JPEG, PNG, WebP либо GIF. Поиск начинается автоматически,
результат остаётся в том же окне; отдельная страница предлагает такой же сценарий.
Страница доступна гостям. [trace.moe](https://soruly.github.io/trace.moe-api/)
возвращает до пяти разных сочетаний аниме/серии: название, время сцены, сходство
и временные превью кадра и видео. При сходстве ниже 90% интерфейс предлагает другой
кадр. Превью 18+ скрыты. Истечение превью не убирает названия и ссылки.
Точное однозначное совпадение названия или псевдонима ведёт к опубликованному тайтлу
AnimeSoul; иначе доступен поиск в каталоге. «Смотреть» показывает сезон, серию и таймкод
и открывает точную зарегистрированную серию с `?t=…#anime-watch`, если сопоставление
однозначно и время не превышает длительность. Для тайтлов с несколькими сезонами
нужен точный сезон; для отдельного сезонного тайтла допустима локальная нумерация
сезона с единицы. Смещения абсолютной нумерации не угадываются. Без сопоставления
кнопка открывает плеер с подписью «Выбрать серию в плеере». Номер сезона берётся
из явного указания в названии или из найденной локальной серии.
Уточнённые `episode_start`/`episode_end` trace.moe имеют приоритет над номером,
извлечённым из имени файла; диапазоны нескольких серий не превращаются в точную ссылку.
Кадр и видео сохраняют пропорции без обрезки; широкая карточка показывает крупное
превью сбоку, узкая — над текстом. Современные превью запрашиваются в размере `l`.
«Показать сцену» включает воспроизведение; «Показать кадр» возвращает изображение.
Сбой каталога не ломает распознавание. Остальные совпадения можно раскрыть под лучшим.

Оба режима делят локальную историю последних 20 успешных поисков по кадру. В ней
сохраняются названия и координаты сцен, без исходных файлов, временных медиа-ссылок
и старых квот. Открытие записи не расходует поиск. Очистка удаляет историю на этом
устройстве. Обычный поиск в шапке также хранит десять последних запросов с отдельной
очисткой. Повреждённое или недоступное хранилище браузера не ломает поиск.

У отдельной страницы настроены canonical, title/description, Open Graph/Twitter,
видимый FAQ и соответствующие структурированные данные FAQ/WebApplication/Breadcrumb.
Она включена в sitemap/robots при публичном HTTPS-развёртывании с `PUBLIC_INDEXING=true`;
локальная и демо-среда остаются закрытыми от индексации. Результаты и история находятся
в клиентском состоянии и не передаются поисковым роботам.

`POST /api/search/frame` принимает байты изображения через прокси сайта с проверкой
Origin, `X-AnimeSoul-Request: 1`, `application/octet-stream` и `no-store`. Оба слоя
ограничивают файл 5 МБ; API проверяет сигнатуру, декодирование и предел 4096 × 4096 /
16 мегапикселей. Для GIF берётся первый кадр. API удаляет метаданные и отправляет JPEG
не более 640 × 360 на фиксированный адрес trace.moe. Файлы и результаты не сохраняются
на сервере, куки сессии и данные аккаунта провайдеру не передаются. Есть отмена, повтор
и обработка таймаута.

`TRACE_MOE_API_KEY` необязателен и используется только на сервере. Без ключа trace.moe
сейчас разрешает 100 поисков за 24 часа на IP сервера и один одновременный поиск.
AnimeSoul выполняет один внешний поиск одновременно и ограничивает маршрут пятью
запросами в минуту на IP в API; пользователи веб-прокси делят этот IP. Для нескольких
экземпляров API нужен общий ограничитель. Квоты, сбои и некорректные ответы дают понятные
ошибки. Превью истекают через пять минут; повтор поиска получает новые ссылки.
Перед коммерческим использованием проверьте [условия](https://soruly.github.io/trace.moe-api/#/terms)
провайдера.
`GET /api/search/frame/quota` выдаёт только общую/использованную/оставшуюся квоту из `/me`,
с кешем на 30 секунд и обновлением через `/me` после поиска: счётчик ответа поиска может
отставать. Оба режима показывают общий лимит
сервера. При недоступной квоте остаток помечается неизвестным, приблизительные числа
не подставляются. IP/email провайдера и ключ в браузер не попадают.

`GET /api/search?q=…` обслуживается API и проксируется на домене сайта с `no-store`.
Необязательная веб-сессия определяет пользователя; передать чужой viewer ID нельзя.
`/search` рендерится на сервере и имеет `noindex`.
API кеширует кандидатов для поиска по названиям/жанрам на 45 секунд: до 20 000 тайтлов
и профилей. Перед выдачей заново проверяются публикация и доступ пользователя.
Количество серий и сохранённый прогресс вошедшего пользователя загружаются заново
для найденных аниме, вне общего кеша кандидатов; прогресс другого аккаунта в ответ
не попадает. Поиск показывает последний прогресс, сохранённый плеером, а не ещё
не записанное воспроизведение.
Сопоставление реализовано в API и общих контрактах. Индексы PostgreSQL full-text/trigram
или отдельный поисковый сервис остаются следующими вариантами при подтверждённой
необходимости по нагрузке или качеству поиска.
