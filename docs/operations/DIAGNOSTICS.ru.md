# Диагностика ошибок

Сайт записывает необработанные ошибки браузера, отклонённые Promise, ошибки границ React, неудачные запросы к API и сбои плеера. Сервер сайта сохраняет ошибки рендера и обращений к каталогу, API — исключения с ответом 5xx.

Журнал доступен в админке в разделе «Ошибки пользователей» владельцу и администраторам после входа с MFA. Можно найти событие по странице, сообщению, коду ошибки, ID пользователя или сессии браузера. Ошибки пользователя и сервера сопоставляются по `digest`, если он есть.

События содержат серверное время, источник, страницу, сообщение, стек, код, подтверждённый сервером ID пользователя, случайный ID сессии браузера и до десяти переходов/запросов перед сбоем. Если API недоступен, событие всё равно сохраняется; ID пользователя будет пустым, события браузера связываются по ID сессии. Клиент не может назначить себе чужой ID пользователя.

Файлы JSONL находятся в `artifacts/diagnostics/YYYY-MM-DD.jsonl`, исключены из Git и не доступны через публичные маршруты. Хранятся семь дней, максимум 4 MiB на день; очистка выполняется при записи нового события. Дубли браузерных ошибок подавляются на пять секунд; отправка ограничена двадцатью событиями в минуту на вкладку и 120 запросами в минуту на сервер сайта. Фильтр админки показывает последние 100 совпадений.

Пароли, cookies, тела запросов и содержимое localStorage не собираются. Query-параметры и URL-фрагменты отбрасываются, известные формы секретов и email в сообщениях/стеках маскируются. Произвольные сообщения ошибок всё равно следует писать без персональных данных.

В production задайте одинаковый абсолютный `DIAGNOSTICS_DIR` для API, сайта и админки и подключите общий приватный том. Без общего тома каждый контейнер хранит только свои события. Для нескольких реплик лимит отправки действует отдельно на процесс. Когда диск недоступен, мониторинг пишет короткое сообщение в stderr и не мешает работе сайта.

Главная сохраняет свой интерфейс при недоступности каталога. Кнопка «Повторить» у подборки повторяет запрос, а кнопка на экране ошибки маршрута использует Next.js `retry()` и заново загружает страницу сегмента.
