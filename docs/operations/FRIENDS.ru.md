# Друзья и приватность

Этап 5 реализован локально. `/friends` содержит поиск публичных пользователей, друзей,
входящие/отправленные заявки, подписки, подписчиков и блокировки. Кнопки есть также в профиле.
Оформление сохраняет существующий стиль AnimeSoul.

На компьютере разделы расположены в боковом меню, на телефоне — в меню из двух колонок.
Поиск и выбранный список находятся в основной области. У каждого раздела свои состояния
загрузки, ошибки и пустого списка. Счётчик показывает загруженные профили и знак `+`, если
доступны следующие страницы. Принятие заявки выделено; удаление друга и блокировка собраны
в меню действий. Анимации учитывают настройку уменьшения движения на устройстве.

Заявку можно принять, отклонить или отменить; друга — удалить. Повторы не создают дубликаты.
Встречные заявки становятся дружбой: оба пользователя уже выразили согласие.
Подписка односторонняя и не открывает разделы «друзьям». Новые заявки и подписки доступны
только к публичным профилям; заявки дополнительно требуют разрешения получателя.
Закрытые профили не ищутся. Ранее полученную заявку можно принять после закрытия профиля.

В `/account` выбираются доступ к профилю и видимость каждого раздела: «Все», «Друзья», «Только я».
Публичность раздела не отменяет ограничение всего профиля. Настройки постов, рецензий и истории
комментариев реализованы в первой части этапа 6; модерация ещё впереди. Скрытая история в профиле
не удаляет публичный комментарий под аниме.

Блокировка одной транзакцией удаляет заявку, дружбу и обе подписки, запрещает последующие
социальные действия и авторизованный просмотр профиля для этой пары. Разблокировка не восстанавливает
связи. Публичные данные остаются доступными гостям. Будущие сообщения, уведомления и комнаты
обязаны проверять ту же блокировку при запросах, событиях и переподключении.

| API                                                    | Назначение                                                                             |
| ------------------------------------------------------ | -------------------------------------------------------------------------------------- |
| GET /api/account/social?section=friends&after=UUID     | Свой список; также incoming/outgoing/following/followers/blocked                       |
| GET /api/account/social/search?q=имя                   | До 20 публичных профилей, минимум 2 символа                                            |
| GET /api/account/social/:userId                        | Собственное отношение, без приватных полей аккаунта                                    |
| POST /api/account/social                               | targetId; action: request/accept/decline/cancel/unfriend/follow/unfollow/block/unblock |
| GET /api/account/profiles/:username                    | Профиль с проверкой владельца, дружбы, блокировки и разделов                           |
| GET /api/account/profiles/:username/friends?after=UUID | Пагинация разрешённого списка друзей; закрытый список даёт 404                         |

Все эти маршруты требуют web-сессию. Мутации требуют Origin, собственный заголовок и CSRF.
Инициатор берётся только из сессии. Ответы и Next proxy используют `no-store`.
Списки содержат до 50 записей, упорядоченных по UUID, и курсор `next`. Собственный список показывает
идентичности своих друзей; чужие списки исключают недоступные профили без раскрытия скрытого числа.
Гостевой DTO содержит до 50 публичных друзей при открытом разделе; для следующих страниц нужен вход.
Закрытый список не выдаёт массив, счётчик или курсор.

`FriendRequest` и `Friendship` хранят одну упорядоченную пару UUID, `Follow`/`UserBlock` — направленные пары.
CHECK проверяет порядок и автора заявки. Все изменения пары блокируют обе строки User в порядке UUID:
встречные заявки и гонки с блокировкой сериализуются. Действия имеют аудит и отдельный лимит
60 за минуту на пользователя в PostgreSQL, переживающий перезапуск.

Старые boolean-флаги читаются как прежние public/private; новые разделы закрыты по умолчанию.
Гостевые DTO, metadata и JSON-LD получают только публичные данные. Авторизованный HTML имеет noindex.
Закрытые профили исключены из sitemap; `invisible` выдаётся как `offline`.
Кириллические имена декодируются один раз и проверяются до обращения к API.

Шесть PostgreSQL-сценариев проверяют сессии/CSRF, направления заявок, гонки, блокировки, аудит,
три уровня доступа, отзыв, прямой запрос списка, пагинацию и лимиты. Отдельный production SSR-тест
проверяет кириллицу, доступ и отсутствие приватного текста в metadata/JSON-LD.
`db:verify` включает восстановление friendship/follow из backup.
Миграция `20261007160000_social_relations` применена к рабочей локальной БД после backup:
прежние поля восьми таблиц и все 13 142 текущих UUID/slug аниме сохранили хеши.
