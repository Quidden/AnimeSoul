# Архитектура основы — 2026-10-06

[Расположение и связи](PROJECT_MAP.ru.md) · [Карта страниц/API](SITE_MAP.ru.md) ·
[Модель данных](DATA_MODEL.ru.md) · [Запуск и настройки](../operations/LOCAL_DEVELOPMENT.ru.md).

Сайт построен как модульный монолит. Один API владеет бизнес-правилами и доступом к базе.
Серверные страницы Next.js получают проверенные публичные ответы API.

| Путь                 | Ответственность                                                |
| -------------------- | -------------------------------------------------------------- |
| apps/web             | Публичные страницы, metadata, JSON-LD, sitemap и интерфейс     |
| apps/api/src/catalog | Чтение опубликованного каталога и публичных профилей           |
| apps/api/src/admin   | Закрытая административная граница                              |
| apps/admin           | Отдельное приложение администрирования без индексации          |
| apps/worker          | Место будущего worker; задания пока не запускаются             |
| packages/contracts   | DTO на Zod, серверная приватность и политика провайдеров       |
| packages/database    | Prisma, миграция, PostgreSQL-клиент и тестовые данные          |
| packages/config      | Общие строгие настройки TypeScript                             |
| infra                | Локальные PostgreSQL/Redis; production будет отдельным этапом  |
| scripts              | Настройка, сборка, управление сервисами и проверка документов  |
| docs                 | Решения, доказательства миграции и эксплуатационные требования |

Приложения зависят от общих пакетов. База используется только сервером.
Ввод проверяется до ограниченного ORM-запроса; сборка SQL из пользовательских строк запрещена.
Единственный raw-запрос сейчас — постоянная проверка готовности SELECT 1.

Сервер Next.js обращается к API через `apps/web/lib/api.ts`: таймаут 5 секунд, no-store
и проверка ответа через Zod. Клиентские `SiteHeader` и `ProfileHeader` отвечают за меню/прокрутку,
а не правила доступа или сохранение. Admin пока не обращается к API.
Redis существует в compose, worker — только как описание: фоновых задач и общего кеша ещё нет.
Общие настройки TypeScript, ESLint и Prettier находятся в `packages/config`.
Скрипты разделены на `scripts/workspace`, `scripts/quality` и `scripts/windows`.

## Настройки

.env приватный. Setup один раз создаёт случайный пароль локальной базы и не перезаписывает настройки.
Сервисы слушают loopback на 8020–8022, база/Redis — на 54329 и 6391.
DEMO_CATALOG включается явно и запрещён API в production.
PUBLIC_INDEXING=true требует публичный HTTPS SITE_URL и запрещает тестовый каталог.
SITE_URL задаёт канонический публичный адрес; API_URL используется только сервером.
Флаги `ALLOW_YUMMY`, `PAYMENTS_ENABLED` и адрес Redis зарезервированы, но ещё не подключены
к runtime. Их изменение не включает отсутствующие адаптеры или платежи.
Потребители переменных — в [инструкции](../operations/LOCAL_DEVELOPMENT.ru.md#настройки-и-их-потребители).

## Публичный API

| Метод и путь                | Результат                                               |
| --------------------------- | ------------------------------------------------------- |
| GET /api/health             | Жив ли процесс, версия; без секретов                    |
| GET /api/ready              | Готовность БД, 200 либо 503                             |
| GET /api/catalog?q=         | До 60 опубликованных аниме, запрос до 100 символов      |
| GET /api/anime/:slug        | Опубликованное аниме либо 404                           |
| GET /api/profiles/:username | Публичный профиль после удаления скрытых полей либо 404 |
| GET /api/sitemap/catalog    | Опубликованные slug и реальные даты изменения           |
| GET /api/sitemap/profiles   | Публичные ники с разрешённой индексацией и даты         |
| Любой /api/admin            | 401 до реализации сессий, прав и MFA                    |

Все ответы API имеют no-store. Закрытые профили и отключённые пользователи не выдаются.
Сервер удаляет скрытые «обо мне», любимое, папки, оценки и статистику.
«Невидимка» снаружи становится «не в сети»; служебная видимость, email и пароль не входят в DTO.
Редактирование владельцем и защищённые DTO будут в этапе 2.

## SEO

Названия и разрешённое содержимое аниме/профиля входят в серверный HTML.
Metadata содержит canonical и описание. Поисковая выдача сайта имеет noindex.
JSON-LD экранируется для script-контекста и соответствует видимым данным; оценки не выдумываются.
Локально действуют noindex, robots disallow и пустой sitemap. Admin всегда закрыт для индексации.
Публичный домен и Search Console будут подключены позже; попадание в поиск пока не заявляется.
Один sitemap не выдаётся при превышении 50 000 URL суммарно: до достижения лимита нужны отдельные файлы. Тестовые записи помечены в базе, не входят в sitemap и имеют noindex даже при предпросмотре из PostgreSQL.

## Текущие границы

Живые провайдеры пока не вызываются. Есть контракт политики Yummy и выключенный флаг окружения.
Адаптер, переключатель с аудитом и очистка кеша появятся в этапе 3.
Платежи имеют базовые таблицы заказа, операции, callback и прав; списания и активация премиума не реализованы.
Нормализация библиотеки, языки, пагинация, медиа, сессии, MFA и метрики идут по плану.

## Оформление и сопровождение

Сохранён привычный тёмный стиль сайта. Общие стили и страницы разделены на
`base`, `header`, `home`, `catalog`, `anime`, `profile` в `apps/web/styles`;
`app/globals.css` подключает их. [Карта оформления](../design/README.ru.md) указывает компоненты.
API состоит из controller/service, shared DTO и серверного пакета БД; `src/modules`
и `packages/ui` пока относятся к целевой структуре, а не текущему коду.
Изменения маршрутов, схемы, настроек и запуска сопровождаются обновлением карт и проверками.
