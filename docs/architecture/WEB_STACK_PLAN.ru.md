# План перехода AnimeSoul на новый стек

**6 октября 2026 года. Статус: реализация начата; архив и основа подготовлены. [Ход работ](../migration/STATUS.ru.md).**

Решения пользователя: desktop исключается из дальнейшей разработки; мобильное приложение отделяется; сайт должен индексироваться по названиям аниме и публичным никам, иметь защищённую админку, статистику и основу для платежей. Продавец ориентируется на Украину, аудитория — международная. Этот документ заменяет первоначальную оценку стека. Подготовка плана не меняет ветки, работающий сайт и платежные аккаунты.

## 1. Целевая архитектура

| Часть                | Решение                                                                                                                                                  |
| -------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Публичный сайт       | Next.js App Router + React + TypeScript. Серверный HTML для аниме, каталога и разрешённых публичных профилей; интерактивные плеер и редакторы на клиенте |
| Сервер               | Node.js актуальной LTS-ветки + NestJS/Fastify. Модульный монолит; бизнес-логика принадлежит API                                                          |
| Данные               | PostgreSQL + Prisma, версионируемые миграции, ограничения БД и транзакции; существующие UUID пользователей сохраняются                                   |
| Админка              | Отдельное приложение Next.js на поддомене `admin`, самостоятельная сессия и проверка прав API                                                            |
| Фоновые задачи       | Worker того же репозитория: импорт каталога, почта, обработка медиа, платежные события и статистика                                                      |
| Redis                | Общие счётчики ограничения запросов, короткоживущий кеш и очередь заданий. Платежи и премиум-права остаются в PostgreSQL                                 |
| Файлы                | S3-совместимое объектное хранилище; отдельные публичные и закрытые области                                                                               |
| Развёртывание        | Docker, development/staging/production, reverse proxy, HTTPS, мониторинг и резервные копии                                                               |
| Мобильное приложение | Отдельный репозиторий `AnimeSoulMobile`, собственные версии, CI, подпись и секреты; общий документированный API сайта                                    |

Next.js обслуживает страницы и обращается к API. Авторизация, роли, платежи и правила профилей не дублируются в Server Actions. `/api` на публичном домене проксируется в backend для одного origin. Админ-домен имеет своё ограниченное проксирование и cookie. Версии зависимостей фиксируются при создании основы. [Next.js server/client](https://nextjs.org/docs/app/getting-started/server-and-client-components), [NestJS/Fastify](https://docs.nestjs.com/techniques/performance).

Для поиска начать с PostgreSQL full-text/trigram по русским, оригинальным и английским названиям, псевдонимам и никам. Отдельный поисковый сервис вводить после измерения качества и нагрузки.

## 2. Структура кода и читаемость

Предлагаемая структура нового `main`:

```text
apps/
  web/                  # публичные страницы и личный кабинет
  api/src/modules/      # auth, users, profiles, catalog, library,
                        # playback, media, entitlements, billing,
                        # analytics, administration, providers
  admin/                # таблицы, формы, отчёты и управление
  worker/               # фоновые задания
packages/
  contracts/            # схемы API, OpenAPI и клиенты без секретов
  database/             # Prisma, миграции, серверный доступ к БД
  ui/                   # общие компоненты и токены оформления
  config/               # общие TS, lint и форматирование
docs/                   # архитектура, API, инструкции и решения
infra/                  # Docker, proxy, deployment и backup
scripts/                # поддерживаемые утилиты
artifacts/              # игнорируемые результаты сборок и проверок
```

pnpm workspace, один lock-файл. В корне — README, конфигурации и каталоги проекта. Python, desktop-упаковка и архивный стек остаются в архивной ветке; мобильного кода в этом workspace нет. [pnpm workspaces](https://pnpm.io/workspaces).

Контроллер отвечает за HTTP, сервис — за сценарий, слой данных — за запросы, адаптер — за внешнего провайдера. Frontend организуется по функциям продукта; сеть и правила прав отделяются от JSX. Длинные формы, монолитные обработчики и общий CSS разбиваются по ответственности. Размер файла сам по себе не является причиной искусственного дробления.

Обязательны строгий TypeScript, проверка входных данных во время выполнения, понятные имена, единое форматирование и отсутствие необоснованного `any`. Комментарии объясняют причину и ограничения. Модули имеют краткое описание назначения; решения фиксируются в ADR. Секреты и пакет БД не импортируются в клиент. Каждый PR — законченная задача с проверкой поведения и актуализацией соответствующих документов.

## 4. Git и сохранение текущей версии

Сейчас ветка называется `master`; есть существенные изменённые и незаписанные файлы, включая сайт и перемещённую документацию. Ветка на текущем HEAD без коммита их не сохранит.

1. Проверить состав исходников и создать снимок всей рабочей версии, включая нужные untracked-файлы. До коммита проверить отсутствие ключей и пользовательских данных.
2. Сохранить коммит в `codex/archive-current-2026-10-06` и отметить тегом `archive-current-2026-10-06`. Архив содержит текущие сайт, desktop, Android и исторический стек с инструкциями.
3. Отдельно сохранить БД, медиа и Android keystore в защищённом хранилище; не помещать их в Git.
4. Из архивного коммита начать `codex/new-web-stack`. Удалять старый код обычными коммитами после снимка; не переписывать историю. В новом `main` оставить новый стек, его документы и поддерживаемые утилиты.
5. Назначить `main` основной веткой после запуска новой основы и CI. До готовности сайта deployment остаётся на зафиксированной архивной версии. Далее — небольшие ветки по этапам, PR и обязательные проверки.

Архив служит для восстановления и сравнений. Старый backend целиком не переносится: переносятся проверенные контракты, данные и отдельные полезные решения.

## 5. Отдельное мобильное приложение

Для совместимых обновлений сохранить прежний applicationId, ключ подписи и увеличивать versionCode.

Вынести Android-код, документы, историю релизов и самостоятельную сборку в `AnimeSoulMobile`. Сборка перестаёт читать desktop-конфигурацию и исходники родительского репозитория. Сначала сохранить нынешнюю Android-реализацию как самостоятельную воспроизводимую основу, чтобы не переписывать одновременно сайт и мобильный плеер.

Новый сетевой режим использует версионированный API и серверную авторизацию. Секреты каталога и платежей остаются на сервере. Локальный runtime, если временно нужен для совместимости, принадлежит только мобильному репозиторию. Офлайн-файлы, PiP, MediaSession, Cast и системные загрузки — задачи Android; общий API хранит аккаунт, библиотеку, права и прогресс. SDK получается из OpenAPI, а не копированием внутреннего backend-кода.

Проверки: обновление с прежней подписью, вход/выход, смена аккаунта, конфликты прогресса, офлайн и отзыв доступа. Нативные покупки — отдельный этап с проверкой правил площадки; веб-оплату нельзя автоматически считать допустимой для цифрового премиума внутри Google Play-приложения. [Правила платежей Google Play](https://support.google.com/googleplay/android-developer/answer/9858738).

## 6. Каталог, данные и провайдеры

У аниме — внутренний ID и соответствия `provider + external_id`; slug, названия, псевдонимы и связи франшиз принадлежат каталогу AnimeSoul. Старые YummyAnime ID переводятся через таблицу соответствий. Ошибки сопоставления попадают в отчёт администратору; ссылки библиотеки сохраняются до разрешения конфликта.

Страницы используют опубликованные метаданные собственного каталога: отказ источника просмотра не удаляет страницу из поиска. Импорт выполняется фоновыми заданиями с таймаутами, квотами и ограничением повторов. Состояния «выключен», «нет ключа» и «ошибка источника» различаются.

YummyAnime получает сохраняемый переключатель в админке и запрет окружения с приоритетом над ним. В production по умолчанию выключен; в личном окружении включается явно. Политика охватывает каталог, fallback, трейлеры, фоновые задачи и проверку токена. Тест подтверждает ноль исходящих запросов при отключении. Production-источники метаданных и просмотра должны допускать выбранный режим использования; это зависимость запуска. [Условия YummyAnime](https://api.yani.tv/).

Перенести UUID аккаунтов, подтверждение почты, Google-привязки, роли, статусы, приватность, избранное, папки, прогресс и оценки. Для старых хешей паролей предусмотреть совместимый верификатор с обновлением при входе либо управляемый сброс. На переключении допускается повторный вход с отзывом прежних сессий. Импорт повторяем, имеет отчёт строк/связей и не превращает demo-данные в реальные аккаунты.

## 7. Индексация и SEO

Цель — доступность для индексации и релевантность запросам «Атака титанов», «Attack on Titan», «Shingeki no Kyojin» и разрешённым публичным никам. Позиции и сроки появления также зависят от контента, конкуренции и поисковика. [Google SEO](https://developers.google.com/search/docs/fundamentals/seo-starter-guide).

### Страницы и адреса

- `/anime/ataka-titanov`: названия и псевдонимы, описание, год, жанры, сезоны, статус, связи и доступные действия.
- `/users/dogem`: ник, разрешённое описание и видимые блоки. UUID сохраняется независимо от ника.
- Страницы жанров, сезонов и редакционных подборок индексируются при полезном содержимом. Комбинации фильтров не порождают тысячи дублей.
- Смена slug/ника даёт постоянный редирект. Старые `/anime/{external_id}` имеют таблицу редиректов. Приватность имеет приоритет над редиректом старого ника.

Текст и ссылки присутствуют в серверном HTML без JS. Плеер загружается отдельно и не задерживает описание; публичные переходы — настоящие ссылки. Первый запуск сохраняет русский контент; локализация `uk/en` предусмотрена моделью. Языковые URL и hreflang публикуются после реальных переводов. [Google: рекомендации разработчикам](https://developers.google.com/search/docs/fundamentals/get-started-developers).

### Технические задачи

- Уникальные title, description, H1, canonical, Open Graph, язык и семантический HTML. Пример: «Атака титанов — сезоны, описание и серии | AnimeSoul». Метаданные формируются сервером. [Next.js metadata](https://nextjs.org/docs/app/api-reference/functions/generate-metadata).
- Sitemap содержит опубликованные аниме и разрешённые профили; lastmod отражает реальное изменение. Robots.txt, правильные 200/404/410/редиректы, каноникализация сортировок и дублей. [Google canonical](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls).
- Admin, кабинет, авторизация, внутренний поиск, персональные папки и результаты оплаты не индексируются. Noindex не заменяет авторизацию, robots.txt не защищает приватные данные. [Ограничения robots.txt](https://developers.google.com/search/docs/crawling-indexing/robots/intro).
- JSON-LD: подходящая разметка произведения/хлебных крошек, ProfilePage/Person для разрешённого профиля. Поля совпадают с видимыми данными, оценки не выдумываются; расширенный результат не гарантируется. [Google ProfilePage](https://developers.google.com/search/docs/appearance/structured-data/profile-page).
- Оптимизация постеров/шрифтов, отсутствие скачков размеров, отложенные GIF/видео, reduced-motion, измерение LCP/INP/CLS. [Core Web Vitals](https://developers.google.com/search/docs/appearance/core-web-vitals).
- Search Console, отправка sitemap и проверка URL после подключения домена; наблюдение за дублями, исключениями, запросами и кликами.

### Приватность при индексации

Отдельная настройка разрешает индексировать публичный профиль. Скрытые «обо мне», любимое аниме, папки, оценки и статистика исключаются сервером из публичного DTO, HTML, RSC, JSON-LD, OG и общего кеша. Личные ответы не кешируются совместно с публичными. Изменение видимости очищает кеш и обновляет sitemap; отключение индексации даёт noindex, закрытие профиля прекращает выдачу данных. Старые копии поисковика исчезают по его графику обработки.

Приёмка: HTML аниме/ника проверяется без JS; sitemap, metadata и редиректы проверяются автоматически. Скрытый блок с уникальной тестовой строкой отсутствует во всех анонимных представлениях, включая исходный HTML и кеш после смены настройки.

## 8. Безопасность с первых этапов

Модель угроз охватывает аккаунты, профили, провайдеров, медиа, администрацию и платежи. Проверять применимые требования OWASP ASVS уровня 2 с результатами и объяснёнными исключениями. [OWASP ASVS](https://owasp.org/projects/asvs).

| Область              | Требование                                                                                                                                                                                                                                                                                                                                                           |
| -------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| SQL-инъекции         | Параметризованные запросы, разрешённые поля сортировки, DTO, минимальные права БД; запрет конкатенации ввода и unsafe raw SQL. ORM сам по себе не снимает риск. [OWASP SQLi](https://cheatsheetseries.owasp.org/cheatsheets/SQL_Injection_Prevention_Cheat_Sheet.html), [Prisma raw queries](https://www.prisma.io/docs/orm/prisma-client/using-raw-sql/raw-queries) |
| Права и чужие данные | Проверка владельца объекта/разрешения на каждом запросе, запрет повышения роли через payload, серверная приватность. [OWASP authorization](https://cheatsheetseries.owasp.org/cheatsheets/Authorization_Cheat_Sheet.html)                                                                                                                                            |
| Пароли и сессии      | Argon2id для новых паролей, случайные сессии с хешами в БД, Secure/HttpOnly/SameSite cookie, отзыв сессий, одноразовые reset-токены. [OWASP passwords](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)                                                                                                                             |
| CSRF и OAuth         | Защита изменений, Origin, точные redirect URI, state/PKCE для подходящего OAuth-потока, ограниченный CORS. [OWASP CSRF](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html)                                                                                                                                       |
| XSS                  | Экранирование текста, очистка разрешённого форматирования, безопасный JSON-LD, CSP с проверкой плеера/GIF. [OWASP XSS](https://cheatsheetseries.owasp.org/cheatsheets/Cross_Site_Scripting_Prevention_Cheat_Sheet.html)                                                                                                                                              |
| Файлы                | Реальный тип, размер, кадры/разрешение, изолированный worker, случайные имена, безопасная выдача; запрет активного SVG/HTML. [OWASP uploads](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html)                                                                                                                                            |
| SSRF                 | Разрешённые схемы/домены, блокировка локальных/служебных IP, проверка DNS/редиректов и лимиты скачивания. [OWASP SSRF](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html)                                                                                                                                       |
| Перегрузка/боты      | Лимиты по аккаунту/IP и стоимости операции, квоты поиска/загрузок, таймауты; IP доверяется только известному proxy                                                                                                                                                                                                                                                   |
| Секреты/ошибки       | Серверное хранение, фильтрация логов, ограниченный мониторинг, ответы без stack trace и токенов                                                                                                                                                                                                                                                                      |
| Поставка             | CI проверяет зависимости, секреты, типы и сборки; непривилегированный runtime, закрытая БД, отдельные секреты окружений, обновления                                                                                                                                                                                                                                  |

Тесты проверяют SQLi, XSS, CSRF, чужие объекты, повышение роли, обход премиума, поддельные сессии, опасные файлы/URL и replay платежей. Проверяется API напрямую. Production не выпускается с неразобранными критическими/высокими уязвимостями.

## 9. Админка и статистика

Приоритет — таблицы, поиск, фильтры, даты, экспорт по правам и ясные сообщения. Готовые компоненты, минимальное декоративное оформление.

Защита: отдельный поддомен и host-only cookie, обязательная MFA/passkey, повторное подтверждение чувствительных действий, отзыв сессий, права по функциям. Разделить владельца, администратора, модератора, аналитика и финансовый доступ. Только владелец выдаёт административные права; первый зарегистрировавшийся не становится владельцем. Изменение роли, провайдера, тарифа и ручного премиума имеет актёра, время, причину и аудит. Cloudflare Access — дополнительный слой с проверкой токена; собственные сессия/права сохраняются.

| Раздел        | Функции и показатели                                                                                     |
| ------------- | -------------------------------------------------------------------------------------------------------- |
| Пользователи  | Регистрации, подтверждение, DAU/WAU/MAU, блокировки, роли, сессии и права                                |
| Каталог       | Опубликованные тайтлы, полнота данных, ошибки импорта/сопоставления, пустые поиски, редактура/редиректы  |
| Провайдеры    | Переключатели, здоровье, запросы, ошибки, p95 задержки, квоты и возраст кеша; секреты замаскированы      |
| Просмотр      | Запуски/ошибки плеера, активные просмотры, популярные тайтлы/озвучки; без секретных URL потоков          |
| Профили/медиа | Жалобы, готовые аватарки/шапки, квоты, ошибки обработки, уникальные статусы и оформление                 |
| Платежи       | Заказы, успех/отказ, возвраты, премиум-права, продления, несверенные операции; суммы отдельно по валютам |
| Безопасность  | Входы/ошибки, лимиты, антибот, MFA/сессии и административный аудит                                       |
| Система       | 5xx, p95 API, очередь, БД/хранилище, backup и дата проверенного восстановления                           |
| SEO           | Sitemap, редиректы, ошибки страниц, ссылки на Search Console; её метрики — отдельная интеграция          |

Каждое число имеет источник, период, часовой пояс и формулу. Публичное «в сети» учитывает выбранный статус; DAU/просмотры считаются отдельно по активности. Боты исключаются из продуктовых показателей по доступной классификации. Аудит append-only по правам приложения; экспорт финансов/персональных данных требует отдельных разрешений. Сроки хранения событий и логов определяются до production.

## 10. Платежи и премиум

Первый кандидат для украинского продавца — WayForPay, альтернативный адаптер — LiqPay. WayForPay заявляет международные карты и регулярные платежи; страны, конверсию и подключение подтвердить для конкретного аккаунта. Украина сейчас отсутствует в списке прямой доступности Stripe для продавцов, поэтому основной план на него не завязан. [WayForPay](https://wayforpay.com/uk), [LiqPay API](https://www.liqpay.ua/doc/api), [Stripe availability](https://stripe.com/global).

Сущности: `plans`, `prices`, `orders`, `payments`, `subscriptions`, `webhook_events`, `refunds`, `entitlements`. Суммы — в минимальных единицах валюты с контролируемой точностью; цена/валюта/срок фиксируются сервером в заказе. Адаптер реализует создание оплаты, проверку подписи, запрос статуса, возврат и доступные подписки. Реальные списания выключены в dev/staging.

Использовать страницу оплаты провайдера: реквизиты карты не проходят через AnimeSoul. Премиум выдаётся после проверенного серверного callback и сопоставления заказа, суммы, валюты и статуса. Browser success не подтверждает оплату. Подпись проверяется по конкретному API; алгоритм Stripe не копируется в WayForPay/LiqPay. [WayForPay Purchase/callback](https://wiki.wayforpay.com/ru/view/852102), [LiqPay callback](https://www.liqpay.ua/uk/doc/api/callback).

События сохраняются до выдачи прав; уникальные ограничения и транзакции исключают повторную активацию. Дубли/задержанные/переставленные callbacks обрабатываются идемпотентно. Worker сверяет неизвестный статус и повторяет временно неудачную обработку. Нужны отмена автопродления, истечение, отказ продления, возврат и правила изменения доступа. Сначала — разовая оплата премиума на срок; автоматические подписки включаются после проверки условий и отмены.

Премиум — серверное право с источником/сроком, отдельно от декоративного статуса и админской роли. Ручная выдача имеет срок и аудит. Готовые обычные и анимированные аватарки/шапки доступны всем; свои загрузки и поиск GIF — премиуму и выше по разрешению. После истечения новые загрузки и поиск запрещены; ранее выбранные медиа сохраняются. Иные правила истечения потребуют отдельного продуктового решения и должны сообщаться до покупки.

До реального приёма определить тарифы, отмену/возвраты, поддержку, согласовать продукт с провайдером и решить учёт платежей продавца. Сейчас — архитектура и sandbox; аккаунт, комиссии и цены выбираются отдельно.

## 11. Cloudflare и запуск

Перед публичным запуском: DNS/proxy, HTTPS до origin, WAF и ограничения запросов по доступному тарифу. Закрыть API/БД и обход через origin: Tunnel либо проверенные сетевые ограничения и аутентификация origin. Admin закрывается Cloudflare Access. [Origin protection](https://developers.cloudflare.com/fundamentals/security/protect-your-origin-server/), [Cloudflare Access](https://developers.cloudflare.com/cloudflare-one/access-controls/applications/http-apps/self-hosted-public-app/).

Turnstile — на регистрацию, восстановление и подозрительные входы. Сервер проверяет токен, hostname/action, срок и повторное использование. Постоянная captcha на публичных страницах мешает индексации. [Turnstile server validation](https://developers.cloudflare.com/turnstile/get-started/server-side-validation/).

Проверенные поисковые боты получают публичные страницы без challenge; определение не основано только на User-Agent. Callbacks имеют маршрут без интерактивной проверки, но с подписью и лимитами. Кабинет, admin, auth и персональные API исключаются из общего CDN-кеша. [Cloudflare verified bots](https://developers.cloudflare.com/bots/concepts/bot/verified-bots/).

Staging закрыт доступом и noindex. Нужны автоматические backup PostgreSQL/медиа, восстановление, мониторинг, алерты и инструкция дежурного. Финальная миграция: остановить записи старого сайта, снять копию, импортировать/сверить и переключить. Откат после новых записей требует переноса этих данных; возврат старой БД сам по себе теряет новые операции. Реальные платежи включаются отдельно после sandbox и production-проверок.

## 12. Проверяемый результат перед запуском

- Чистый `main` запускается по README; старый стек/Android не участвуют в сборке сайта.
- Архив восстанавливается, UUID/библиотеки сверены, миграция повторяема; проверены хеши и политика сессий.
- HTML аниме содержит названия/описание/metadata; разрешённый профиль содержит ник и только публичные блоки; sitemap/robots/canonical/редиректы проверены.
- Готовые GIF доступны обычному пользователю; загрузка/поиск разрешены действующим серверным правом.
- Административные операции проверяют MFA, сессию, права и аудит; владелец не назначается по очереди регистрации.
- При выключенном YummyAnime нет запросов к нему; библиотека сохранена, каталог использует допустимый источник.
- Sandbox проверяет успех/отказ, подделку, дубль, задержку, возврат и истечение; browser success не выдаёт права.
- Безопасность и нагрузка проверены, формулы метрик документированы, антибот не ломает SEO/callbacks.
- Backup восстановлен отдельно; назначены ответственные за алерты, обновления, модерацию и сверку платежей.

До запуска уточняются домен/хостинг, production-источник каталога, бюджет, публичные языки и цены. Это не мешает начать со снимка, структуры и контрактов API. Календарные оценки составляются после инвентаризации и первой работающей основы; порядок работ определяется условиями завершения этапов.
