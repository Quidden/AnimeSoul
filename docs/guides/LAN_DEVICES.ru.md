# Устройства в локальной сети

В «Настройки → Устройства» можно связать Windows/Android-клиенты для обмена
сохранениями, получения скачанных серий и управления чужим плеером. Интернет для
локального обмена не требуется. Оба приложения должны быть открыты и доступны
друг другу в сети. Обмен по умолчанию выключен.

## Привязка

1. Включите локальный обмен на обоих устройствах.
2. На первом нажмите «Показать код». На втором введите показанные IPv4 и четыре
   цифры кода. Код действует пять минут, используется один раз; после пяти неверных
   попыток нужно показать новый код. Статус «Связано · в сети» появится на обоих.
3. В карточке связанного устройства при необходимости настройте разрешение управлять
   **этим** устройством и приоритет пульта. Управление первоначально запрещено.

Постоянный UUID и ключ связи сохраняются в `animesoul-devices.json` рядом с данными
приложения. При смене IP отредактируйте адрес в карточке устройства: UUID и ключ
останутся прежними. Автоматического обнаружения сменившихся адресов пока нет.
«Отвязать» удаляет доверие на текущем устройстве; на втором может остаться карточка
без соединения. Выключение обмена закрывает LAN-сервер и отменяет передачи.

Используется отдельный TCP-порт **48765**. В Windows приложению может потребоваться
разрешение брандмауэра для частной сети. Гостевые Wi-Fi-сети с изоляцией клиентов
не подходят. IPv6 и фоновые передачи при приостановленном Android-приложении в
этой версии не поддерживаются.

## Сейвы и Google Drive

Сервер опрашивает связанные устройства примерно раз в десять секунд; интерфейс
примерно с тем же интервалом объединяет полученные данные с текущим состоянием.
При медленном или недоступном устройстве цикл может занять больше времени.

Профили сопоставляются по ID. «Основной» (`default`) на двух устройствах считается
одним профилем. Другие ID сохраняются отдельно, даже если названия одинаковы.
Передаются избранное, папки, прогресс, оценки, отслеживание и данные очистки истории.
Темы, настройки плеера, API-ключи, OAuth-токены и привязки не передаются.

Используются существующие правила слияния Google Drive: отметки времени отдельных
серий и полей, сбросы прогресса и удаления. Более поздняя перемотка назад не
заменяется самым большим когда-либо достигнутым временем. При равных ревизиях
действуют существующие правила слияния; корректные часы на устройствах важны.

Полученные изменения применяются к актуальному состоянию интерфейса и проходят
обычное автосохранение. Оно запускает Google Drive, если пользователь уже
настроил облачную синхронизацию. LAN не обходит выбор первого облачного слияния и
не требует Google-авторизации. В слиянии также учитывается последняя версия файла
на диске, которую мог обновить облачный сервис. Если во время запроса пользователь
изменил прогресс или профиль, устаревший ответ пропускается до следующего цикла.

## Серии

В карточке отправителя на принимающем устройстве откройте «Скачанные серии и пульт», затем
«Показать скачанное на устройстве». Выберите серии и нажмите «Получить выбранные».
Обратное направление работает тем же способом с другого устройства.

Передаются MP4, постер, превью и метаданные: ID аниме/исходной серии, сезон, номер,
озвучка, качество, длительность и пропуски. Каждый файл проверяется по размеру и
SHA-256. Только после полной проверки серия попадает в обычный индекс скачанного;
Android публикует её через MediaStore. Дубликаты определяются по обычному ID серии.
Обрыв не регистрирует неполный файл. Повторная попытка начинает файл сначала;
передачи не восстанавливаются после перезапуска процесса.

Старые HLS-пакеты пока не переносятся: для них возвращается понятная ошибка.
Одновременно с LAN-передачей обычные загрузки и удаление сериализуют изменения
индекса, чтобы не терять записи друг друга.

## Пульт

Доступны запуск/пауза, перемотка, предыдущая/следующая серия, выбор сезона, серии и
озвучки, открытие скачанного аниме или другого аниме по ID каталога. Онлайн-тайтлы
всё ещё требуют интернета и настроенных источников на принимающем устройстве.
Браузер может запрещать запуск видео без локального жеста; ошибки прямого плеера
возвращаются пульту. Внешний iframe Kodik подтверждает только отправку команды.

При включённом локальном приоритете действие на устройстве блокирует пульты на
десять секунд. Между пультами действует пятнадцатисекундное владение: больший
приоритет может перехватить управление, равный — ждёт. Команды имеют срок жизни,
ID для устранения повторов и подтверждение обработки интерфейсом. При закрытом
или приостановленном интерфейсе команды не накапливаются для будущего запуска.

## Протокол и проверки

Обычный API с настройками и ключами не публикуется в LAN. Управление привязками
доступно только через loopback с проверкой Origin/Host. Отдельный LAN-сервер
принимает только локальные IPv4-адреса и подписанные запросы: HMAC-SHA256 связывает
метод, путь, ID отправителя, одноразовый nonce сервера и тело. JSON-ответы также
подписаны, файлы проверяются по подписанному манифесту. Четырёхзначный код
временный; после привязки устройства сохраняют длинный случайный ключ. HTTP-трафик
не шифруется, поэтому используйте доверенную локальную сеть.

Это протокол для доверенной локальной сети: содержимое передаётся по HTTP без
шифрования, хотя подделка и повтор подписанных запросов блокируются. Доступ к
приглашению или файлу привязок означает возможность действовать от имени устройства.

Основные файлы: `backend/app/api/lan.py`, `services/lan*.py`,
`frontend/src/features/devices/`. Регрессионные проверки находятся в
`backend/tests/test_lan.py`; публикация MediaStore проверяется с подменой Android-моста.
Полный сценарий Windows ↔ физический Android требует отдельной проверки на устройствах.
