## Следующий выполненный блок: идентичность аккаунта

Добавлены Google Authorization Code + PKCE, state с привязкой к браузеру, nonce и проверка
подписанного ID token. Совпадение почты не привязывает чужой Google к существующему аккаунту:
для привязки нужны текущая сессия и пароль. Google-only аккаунт приватен и не получает роли.

Подтверждение почты, подтверждаемая смена адреса и сброс/создание пароля используют одноразовые
ссылки с хешами в БД. Смена почты/пароля отзывает web/admin-сессии; прежние ссылки инвалидируются
версией аккаунта. Почта отправляется через SMTP; локальный режим сохраняет тестовые письма
в игнорируемом `artifacts/dev-mail` и запрещён в production.
Добавлены выбор доверенных аватаров/баннеров и текущая идентичность в шапке.

`pnpm db:verify`: 26 проверок без пропусков, включая конкурентный reset, одноразовые ссылки,
отзыв обеих audiences, Origin/CSRF, PKCE, подписи JWT, неверные issuer/audience/nonce,
просроченный state, replay и запрет автоматической привязки по почте; backup/restore прошёл.
Настоящий Google consent и внешняя SMTP-доставка требуют credentials и ещё не проверены.
[Настройка аккаунтов](../operations/ACCOUNTS.ru.md).

Итоговый `pnpm check` прошёл: 41 тест, из них 19 без БД; все 22 PostgreSQL-теста
дополнительно проходят в `db:verify` (26 проверок с повторяющимися общими сценариями).
Форматирование, 344 локальные ссылки и audit зависимостей прошли.
Миграция применена к рабочей локальной БД после backup: прежние поля восьми таблиц
и все UUID/slug аниме сохранили хеши. Live Next proxy проверил options, отмену OAuth,
`no-referrer`, локальную запись тестового письма и страницы account/library/catalog.
