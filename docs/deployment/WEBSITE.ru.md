# Аккаунты сайта и развёртывание

`ANIMESOUL_RUNTIME=website` включает отдельный многопользовательский серверный
режим. По умолчанию работает `local` с прежними сохранениями Windows/Android.
Аккаунт сайта владеет своей библиотекой; переносимые профили внутри неё остаются
доступны как отдельные наборы настроек и прогресса.

## Реализовано

Для существующей базы перед запуском примените `alembic upgrade head`
(миграция `0002_user_profiles`). API профиля: GET `/api/profiles/me`,
GET `/api/profiles/{id}`, PATCH `/api/auth/profile` с частичным обновлением
полей и `visibility`, POST `/api/profiles/presence`. Запись проверяет сессию,
ID аккаунта и CSRF.

Редактор предлагает готовую библиотеку AnimeSoul: обычные и анимированные
аватарки и шапки доступны всем зарегистрированным пользователям. Свои файлы,
прямые ссылки и встроенный поиск GIF доступны роли «Премиум» с разрешением
`profile.customize`, ролям выше с этим разрешением и администрации. Сервер
проверяет право при каждом изменении изображения; название роли его не выдаёт.
GET `/api/profiles/media-options` возвращает библиотеку и доступные действия.

Для поиска задайте `ANIMESOUL_GIPHY_API_KEY` в env сервера. Это публичный ключ
веб-интеграции, который передаётся клиенту. Поиск идёт напрямую в
[GIPHY API](https://developers.giphy.com/docs/api/), без прокси и кеширования.
Выбор сохраняет `giphy:ID`; профиль заново получает актуальный адрес GIF по ID.
В интерфейсе используется официальная подпись Powered by GIPHY. Без ключа
библиотека и загрузка своих файлов продолжают работать.

- Главная, каталог, страницы аниме и плееры источников доступны гостям. Вход
  открывается по кнопке в шапке. Гостевой браузерный кеш отделён от аккаунтов;
  запросы к сейвам аккаунта без входа не выполняются.
- Регистрация по email/паролю, вход, выход, подтверждение почты, сброс пароля,
  смена логина, пароля и почты с подтверждением нового адреса.
- Google-вход через authorization code с PKCE, одноразовым state, привязанным к
  браузеру, nonce и проверкой ID-токена официальной библиотекой Google. Связь
  хранится по Google `sub`. Совпадение почты не объединяет аккаунты автоматически:
  существующий аккаунт привязывает Google после входа в своём профиле.
- Стеклянный профиль `/account`, настройки безопасности `/account/settings` и
  публичная ссылка `/users/{id-пользователя-в-БД}`. Аватарка и шапка принимают
  готовые варианты для всех; с премиумом — PNG/JPEG/GIF/WebP до 1 МБ,
  прямую HTTPS-ссылку или выбор GIF; GIF сохраняет анимацию.
  Ник, «обо мне», присутствие и приватность сохраняются в БД. Значки админа,
  премиума и уникальных статусов берутся из назначенных ролей; предусмотрены
  CSS-атрибуты для будущих рамок и анимаций.
- Каждый блок можно скрыть: «обо мне», любимое аниме, подборки, личный рейтинг,
  статистика. Разделы библиотеки изначально закрыты. Сервер исключает скрытые
  разделы из публичного ответа, а также почту, разрешения, заметки в папках и
  сырую историю просмотра. Владелец может открыть «Вид для других». Контент
  берётся из активного профиля библиотеки.
- Сохраняемые статусы: в сети, не в сети, не беспокоить, невидимка. Невидимка
  для других всегда не в сети. Онлайн/«не беспокоить» публично сменяются на
  офлайн через 180 секунд без heartbeat видимой вкладки; выбранный режим
  сохраняется. При прокрутке компактные аватарка и ник появляются в липкой
  шапке сайта.
- Админ-панель `/admin`: поиск пользователей, назначение ролей, создание и
  редактирование своих ролей, настройка разрешений и журнал изменений.
  Встроенная роль плеера даёт `player.use`, роль скачивания — `downloads.use`.
  Роль «Премиум» даёт `profile.customize`; она назначается через админ-панель.
  `admin.users` и `admin.roles` позволяют
  делегировать управление. Права управления выдаёт только владелец; защищённые
  роли нельзя редактировать.
- PostgreSQL хранит пользователей, Google ID, хеши сессий, роли, одноразовые
  токены, аудит, сейвы, профили и элементы сейвов. Избранное, папки, отслеживание,
  прогресс и оценки представлены отдельными строками таблиц. Расширяемые поля
  элементов хранятся в JSON-колонках; файлов пользовательских сейвов нет.
- Сейвы изолированы по аккаунту и проверяют серверную ревизию. При конфликте
  вкладок сервер отвечает 409 и требует перезагрузки. Записи клиента выполняются
  последовательно. Браузерный кеш разделён по аккаунтам; новый аккаунт никогда
  автоматически не получает старые данные другого пользователя из браузера.

В примере окружения владельцем указан `dogemmoze@gmail.com`. Назначение происходит
один раз, только после подтверждения этой почты письмом или Google. Последующая
смена почты владельца не передаёт права. Первый зарегистрировавшийся пользователь
не получает привилегий по порядку регистрации.

## Развёртывание

На сервере нужны Docker с Compose, домен с DNS-записью на сервер и открытые порты
80/443. Порты PostgreSQL и приложения наружу не публикуются.

1. Скопируйте [`../deploy/.env.example`](../../app/deploy/.env.example) в `app/deploy/.env`.
2. Укажите домен, точный HTTPS origin, длинный случайный пароль PostgreSQL и
   соответствующий URL БД. Спецсимволы пароля в URL требуют URL-кодирования.
3. Настройте Google и SMTP по разделам ниже. Ключи источников задаются только
   переменными окружения сервера.
4. Из `app/deploy` выполните `docker compose up --build -d`. Compose дождётся БД,
   применит миграции Alembic и запустит приложение за Caddy. Caddy автоматически
   получает HTTPS-сертификаты.
5. Зарегистрируйтесь или войдите через Google с почтой владельца и подтвердите
   её. В `/account` откройте управление пользователями и назначьте нужные роли.

[`../deploy/compose.yaml`](../../app/deploy/compose.yaml) содержит постоянные тома БД и
кеша. [`../deploy/Dockerfile`](../../app/deploy/Dockerfile) собирает frontend без source
maps и запускает приложение от непривилегированного пользователя с корневой
файловой системой только для чтения. Миграции выполняет отдельный одноразовый
сервис.

Не публикуйте порт приложения напрямую: Uvicorn доверяет forwarded-заголовкам
из внутренней сети reverse proxy. Перед запуском нескольких процессов приложения
проверьте ограничения аккаунтов источников и поведение серверного кеша.

## Локальный предпросмотр

Из `app` запустите `python -m tools.website_preview --live-catalog --provider-env deploy/.env`.
На `http://localhost:8013` будут работать настоящий каталог и плеер с ключами
YummyAnime/Kodik из указанного файла. Из него читаются только ключи источников;
настройки production-БД, домена, SMTP и Google не переносятся в предпросмотр.
Аккаунты и сейвы предпросмотра временные; email и OAuth отключены.

Без `--live-catalog` работает изолированный предпросмотр интерфейса:
`--profile-demo` добавляет восемь тестовых карточек, но просмотр аниме в этом
режиме недоступен. GET `/api/health` сообщает `catalog: "live"` или `"demo"`.
После изменения ключей перезапустите сервер. Обычный backend читает
`app/backend/.env` и `app/.env`; `app/deploy/.env` автоматически читает Docker
Compose, а локальный предпросмотр — только при явном `--provider-env`.

## Google

Создайте OAuth-клиент типа Web application и добавьте redirect URI:

```text
https://ВАШ_ДОМЕН/api/auth/google/callback
```

Заполните `ANIMESOUL_AUTH_GOOGLE_CLIENT_ID` и
`ANIMESOUL_AUTH_GOOGLE_CLIENT_SECRET`. Настройте экран согласия и тестовых
пользователей либо публичную доступность в Google Cloud. Это отдельные параметры
от OAuth локального Google Drive. Запрашиваются только `openid email profile`;
Google access/refresh-токены не сохраняются.

Официальная документация: [OpenID Connect — server flow](https://developers.google.com/identity/openid-connect/openid-connect).

## Почта и источники

Заполните `ANIMESOUL_SMTP_HOST`, `ANIMESOUL_SMTP_PORT`, `ANIMESOUL_SMTP_FROM` и при
необходимости логин/пароль SMTP. Порт 587 использует STARTTLS, 465 — TLS с момента
соединения. В production TLS обязателен. Почтовый провайдер должен разрешать
отправку с указанного адреса/домена. Регистрация по почте отключена до настройки
SMTP; Google-вход работает независимо. Ссылки подтверждения и смены почты живут
час, сброса пароля — 30 минут. Токены находятся во фрагменте URL, используются
однократно и хранятся только в виде хешей.

Каталог использует `YUMMYANIME_TOKEN`. Серверный плеер использует
`ANIMESOUL_KODIK_PUBLIC_KEY` и `ANIMESOUL_KODIK_PRIVATE_KEY`. Ключи не возвращаются
клиенту и не меняются через публичное API. Плееры источников через iframe остаются
доступны. Разрешение `player.use` защищает собственный плеер AnimeSoul и endpoint
получения прямых потоков, в том числе при ручном запросе API. Отзыв права запрещает
получать новые потоки; уже выданные внешние ссылки живут до истечения срока у
источника.

`downloads.use` отдельно защищает POST `/api/kodik/download`. В админ-панели
можно выдать роли «Доступ к плееру» и «Доступ к скачиванию» либо создать роль с
обоими разрешениями для будущей подписки. Платежи и сроки подписок пока не
реализованы. Для доступа нужны действующая сессия и подтверждённая почта.

Скачивание на странице аниме сохраняет выбранные серии на устройство пользователя,
без общей серверной офлайн-библиотеки. При поддержке браузером выбора папки файлы
записываются потоково. В остальных браузерах используется загрузка файла с
лимитом буфера 1 ГБ на серию; браузер может потребовать разрешить несколько
скачиваний. Прямые видео и fMP4 сохраняются в MP4, обычный HLS — в TS. TS можно
открыть в совместимом видеоплеере. Поддерживаются VOD-плейлисты, byte ranges и
AES-128; отдельные аудиодорожки и другие виды шифрования требуют другого источника.
Внешний источник должен разрешать браузерные запросы через CORS. Реальная
совместимость с провайдером ещё требует проверки с рабочими ключами.
При выходе или смене аккаунта активное скачивание отменяется. Каждый новый запрос
ссылок проверяет текущие права; ранее выданные ссылки истекают у провайдера.

## Безопасность

Пароли хешируются Argon2id. Непрозрачные сессии хранятся в PostgreSQL как хеши,
действуют семь дней и меняются после входа. Production-cookie используют
`Secure`, host-префиксы, `HttpOnly` для сессии и `SameSite`. Смена чувствительных
данных требует текущий пароль; для Google-аккаунта без пароля нужен вход не
старше пяти минут. Смена/сброс пароля и подтверждённая смена почты завершают
прежние сессии. Каждый авторизованный изменяющий запрос проверяет ID аккаунта,
точный Origin и привязанный к сессии CSRF-токен. Лимиты запросов хранятся в БД и
работают между процессами.

В серверном режиме действуют явный список API, проверка Host, ограничение размера
тела запроса, CSP, запрет встраивания сайта, no-sniff, referrer policy и HSTS.
Функции файловой офлайн-библиотеки, LAN, Discord, Google Drive, изменения ключей
и Watch Party недоступны; соответствующие разделы скрыты. Общие анонимные оценки
можно читать; личные оценки сайта сохраняются в аккаунте без публикации
анонимных голосов локального приложения.

Для реальной эксплуатации ещё нужны Google/SMTP credentials, DNS/HTTPS и проверка
на сервере. Локальные Windows-проверки не выполняли реальный обмен с Google,
отправку почты, Docker-сборку или запуск PostgreSQL. Отдельный CI запускает тесты
аккаунтов на PostgreSQL.

Серверные зависимости закреплены в `requirements-server.txt` и
`requirements-website.txt`; CI проверяет их через `pip-audit`. Для повторной
проверки из `app` выполните `python -m pip_audit -r backend/requirements-website.txt`
после установки `pip-audit`. Зависимости интерфейса проверяются командой
`npm audit --omit=dev` из `app/frontend`.

## Локальный тест с серверным окружением

На ПК используйте тот же [`../deploy/compose.yaml`](../../app/deploy/compose.yaml) и
Dockerfile, что и при деплое: PostgreSQL 17, Alembic, приложение и Caddy. Нужен
Docker Desktop с Linux containers. Пример локального окружения:
[`../deploy/.env.local.example`](../../app/deploy/.env.local.example). Скопируйте его в
`app/deploy/.env`, если файл ещё не создан, задайте случайный пароль БД в двух
параметрах и перенесите ключи источников, Google и SMTP. `app/.env` остаётся
конфигурацией запуска Python на хосте; Docker Compose читает `app/deploy/.env`.
Файлы с реальными секретами исключены из Git и Docker build context.

Локальные параметры:

```dotenv
ANIMESOUL_DOMAIN=localhost
ANIMESOUL_PUBLIC_ORIGIN=https://localhost
ANIMESOUL_WEBSITE_DEVELOPMENT=0
ANIMESOUL_BIND_ADDRESS=127.0.0.1
ANIMESOUL_DATABASE_URL=postgresql+psycopg://animesoul:ПАРОЛЬ_БД@db:5432/animesoul
```

`db` — имя сервиса внутри Docker. PostgreSQL и приложение не публикуют порты;
Caddy принимает подключения только с этого ПК. Работают серверные Secure-cookie,
CSRF и HTTPS; SQLite и ослабленный режим разработки не используются.
`-p animesoul-local` отделяет контейнеры и постоянные тома локального стенда.
Сейвы и аккаунты сохраняются в томе PostgreSQL после остановки контейнеров.

```powershell
# Рабочий каталог: app/deploy. Сначала заполните .env.
docker compose -p animesoul-local up --build -d
```

Compose дождётся PostgreSQL и применит миграции перед запуском приложения.
Для `localhost` Caddy создаёт локальный центр сертификации. Чтобы браузер доверял
HTTPS, после запуска скопируйте его публичный корневой сертификат и добавьте в
хранилище доверенных корневых сертификатов текущего пользователя Windows:

```powershell
New-Item -ItemType Directory -Force ../.website-local | Out-Null
docker compose -p animesoul-local cp gateway:/data/caddy/pki/authorities/local/root.crt ../.website-local/caddy-local-root.crt
Import-Certificate -FilePath ../.website-local/caddy-local-root.crt -CertStoreLocation Cert:\CurrentUser\Root
```

Откройте `https://localhost`. Origin должен точно совпадать; не заменяйте
`localhost` на IP в браузере. Установка сертификата доверяет локальному центру
Caddy для текущего пользователя. Его приватный ключ остаётся в томе Caddy;
копируется только публичный сертификат. При удалении этого тома сертификат
нужно установить заново. Подробнее: [Caddy Local HTTPS](https://caddyserver.com/docs/automatic-https#local-https).

Без SMTP регистрация по email отключена; без Google credentials кнопка Google
недоступна. Для Google OAuth-клиента типа Web application добавьте точный redirect
URI `https://localhost/api/auth/google/callback` и свою почту в тестовые
пользователи, если приложение Google находится в режиме Testing. Google-вход
работает независимо от SMTP. Почта владельца — `dogemmoze@gmail.com`; права
назначаются только после подтверждения адреса.

Остановка: `docker compose -p animesoul-local stop`. Повторный запуск:
`docker compose -p animesoul-local up -d`. Не используйте `down -v`, если хотите
сохранить аккаунты и сейвы. Перед переносом на сервер смените origin, домен,
адрес привязки портов и credentials по серверному примеру окружения; данные
переносите резервной копией PostgreSQL.

## Проверки

Из `app` установите `backend/requirements-website.txt` в виртуальное окружение.
Для запуска Python вне Docker переменные процесса имеют приоритет над файлами;
прежний `app/backend/.env` имеет приоритет над `app/.env`, если оба существуют.

Укажите `ANIMESOUL_TEST_DATABASE_URL` для отдельной PostgreSQL БД тестов, чтобы
прогнать те же контракты на PostgreSQL. Каждый тест создаёт и удаляет свою
временную схему; существующие таблицы аккаунтов не затрагиваются. Команда тестов
аккаунтов: `python -m unittest discover -s backend/website_tests -v`. Прежний набор
локальных тестов: `python -m unittest discover -s backend/tests -v`.

## Эксплуатация

Регулярно делайте резервные копии PostgreSQL и проверяйте восстановление. Перед
обновлением схемы создавайте бэкап; при обычном обновлении не удаляйте тома Compose.
Кеш источников в runtime-томе не заменяет БД аккаунтов. При ротации OAuth/SMTP/ключей
источников меняйте окружение сервера и пересоздавайте web-контейнер. Защитите
бэкапы, env-файлы и почту администратора. Восстановление владельца пока требует
доверенного доступа оператора к БД; публичная админ-панель не передаёт владение.
