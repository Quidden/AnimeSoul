# Discord Rich Presence

Экспериментальная независимая интеграция для Windows. По умолчанию выключена.
Настройки находятся в отдельном разделе **Discord** и хранятся в localStorage
устройства (`animesoul:discord-device-v1`), вне профиля и облачных сейвов.

## Подключение

В сборке уже задан публичный Application ID AnimeSoul: `1554513653909422140`.
Обычным пользователям достаточно оставить поле Application ID пустым и включить
активность. Создавать собственное приложение Discord не требуется.

Для владельца приложения или настройки собственного ID:

1. Создать приложение AnimeSoul в https://discord.com/developers/applications.
2. Загрузить логотип в Rich Presence Art Assets с ключом `animesoul`.
3. Указать публичный Application ID в настройках либо перед запуском задать
   `ANIMESOUL_DISCORD_APPLICATION_ID` для стандартного ID продукта.
4. Запустить клиент Discord на том же ПК и включить публикацию в AnimeSoul.
   В Discord также должно быть разрешено отображение активности.

Токены бота, OAuth и пароль Discord не нужны. Главное название приложения
берётся из регистрации Discord. Можно скрывать название аниме, сезон, серию,
логотип, менять порядок строк и формат времени. На паузе, в библиотеке и при
текстовом таймкоде встроенный счётчик показывает время текущего сеанса приложения.
Начало сеанса сохраняется между обновлениями активности; режим «Не показывать»
не отправляет таймер. Дополнительно можно скрыть всю активность на паузе. Без плеера показывается
«В библиотеке», если эта опция включена.

В коротком статусе под именем пользователя во время просмотра показывается
название аниме, независимо от порядка строк карточки. Если название скрыто
в настройках или просмотр не запущен, короткий статус показывает AnimeSoul.

## Границы

- Браузер подключается только к локальному серверу. HTTP-маршруты проверяют
  адрес клиента, Host и Origin. Посетитель общего сервера не управляет Discord
  на сервере. При размещении за прокси отключить модуль серверным флагом ниже.
- Desktop использует узкий `pywebview.api.discord_presence` мост напрямую в
  локальный модуль. Он не зависит от API каталога и пригоден для будущего
  desktop-клиента общего сервера. Сам режим запуска с удалённым сервером эта
  функция не добавляет; загрузчик сейчас открывает локальный интерфейс.
- Android не показывает этот раздел и не публикует активность.
- Позиция берётся из событий собственного/офлайн-плеера и Kodik. Для источников
  без событий времени подробная активность не публикуется.
- Обновления отправляются не чаще раза в 15 секунд
  (одинаковые данные повторно не отправляются). Начало сеанса сбрасывается
  после отключения интеграции или потери heartbeat, а не при обновлении данных.
  Отключение очищает статус
  сразу после получения запроса. Потеря heartbeat очищает его через 45 секунд.
  После перезапуска Discord выполняется повторное подключение.
- Сервер без открытого интерфейса не публикует «В библиотеке»: требуется
  подтверждение от клиента с включённой настройкой. В нескольких вкладках
  активный просмотр имеет приоритет над библиотекой; несколько одновременных
  просмотров используют последний пришедший снимок.

## Отключение / архивирование

- `VITE_ANIMESOUL_DISCORD_ENABLED=0` при сборке скрывает вкладку и поиск,
  выключает отправку событий.
- `ANIMESOUL_DISCORD_ENABLED=0` перед запуском блокирует backend и desktop-мост.
- Основной код: `frontend/src/features/discord/`,
  `backend/app/services/discord_presence.py`, `backend/app/api/discord_presence.py`.
- Точки подключения: два хука в App/Player, вкладка SettingsCenter, каталог
  настроек и CSS, router/lifespan в main.py, js_api в run.py. Нет новых внешних
  зависимостей и изменений формата пользовательских сейвов.

Проверки: `python -m unittest backend.tests.test_discord_presence` из `app/`,
`npm run check` из `app/frontend/`. Живую карточку нужно проверить с реальным
Application ID, загруженным логотипом и работающим Discord.
